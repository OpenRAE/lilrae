# Review And Repeat Workshop QA

Use this guide to compare historical workshop evidence or plan a candidate qualification.
You need the candidate's release inputs and an approved isolated test VM or CI job.
Do not run lab operations or tests on the developer workstation.
The result is a candidate-specific QA record with each observed outcome and cleanup result.

## Prepare A Candidate Check

Use [manual release QA](../../testing/smoke-test-plan.md) for the current release.
Use [Workshop setup](../setup.md) for the released desktop-seat lesson.
Record the source revision, installed assets, selected scenario, host boundary, and tool versions.
Complete the learner route through actual participant tools and browser access.
Record failures as failures; do not bypass admission or start raw Compose services to claim readiness.

## Record The Result

Record activity times, target, source address, matching alerts, and any required reset proof.
Keep provider credentials and generated private state outside the report.
After retaining required evidence, close agents and perform project-scoped cleanup.
Record whether cleanup succeeded before releasing the assignment.

## Compare Historical Evidence

Read the [original August QA record](records/qa.md) for exact commands, outputs, and observed results.
The old proof used a particular host and temporary range repairs.
It includes retired services and does not qualify the current seat launcher.
Do not claim that its historical success establishes a current passing test.
The remaining sections preserve links into that source record.
